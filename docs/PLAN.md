# План разработки

**Платформа:** мобильный телефон (портрет). Веб-игра + PWA: полноэкранный режим, установка на главный экран, офлайн-кэш, safe-area для вырезов экрана, тач-управление в первую очередь. Упаковка в App Store / Google Play через Capacitor — без изменений кода, когда будут Xcode и Android SDK.

Приоритет: сначала полностью играбельный и интересный цикл одного уровня, затем — контент и полировка.

## Этап A — Фундамент (P0)
1. Vite + TypeScript, структура `core / config / sim / render / ui`.
2. Цикл с фиксированным шагом, масштабирование холста под экран (портрет 540×960, DPR).
3. Ввод: относительный drag (pointer) + клавиатура.
4. Seeded RNG, пулы, пространственная сетка.

## Этап B — Ядро геймплея (P0)
1. Отряд: лидер, строй-спираль, HP бойцов, смерть, передача оружия.
2. Оружие: данные + стрельба, пули, пробивание, AoE, огонь, луч.
3. Зомби: ходок, бегун; движение, наведение, раздвигание, контакт.
4. Объекты: тайник, патроны, клетка, аптечка, бочка, препятствия, монеты.
5. Режиссёр уровня: генерация трека по конфигу + непрерывный спавн по кривым.
6. Финиш уровня, поражение, подсчёт итогов.

## Этап C — Представление (P0)
1. Процедурные спрайты (кадры ходьбы + вспышка) для всех юнитов и объектов.
2. Фон глав: дорога-тайл, декорации обочин.
3. Эффекты: вспышки, трассеры, частицы, кровь/трупы, взрывы, тряска, всплывающий текст.
4. HUD.

## Этап D — Мета и экраны (P1)
1. Сохранение, экономика, улучшения, казарма/звания.
2. Титул, карта кампании, карточка уровня, итоги, поражение, пауза, улучшения, финал.

## Этап E — Контент (P1)
1. Все типы зомби (брут, толстяк, плевун, омоновец, крикун, ползун).
2. Все виды оружия и классы союзников, усиления, ящик «?».
3. События: орда, развилка, сужение, автобус, сброс груза, фланги, минное поле, ночь.
4. 4 босса.
5. 16 уровней + бесконечный режим.

## Этап F — Мобильная платформа (P1)
1. PWA: manifest, иконки, service worker, `apple-mobile-web-app-capable`, блокировка зума/скролла/долгого тапа.
2. Safe-area (вырез экрана), адаптация HUD под маленькие экраны, пауза при сворачивании.
3. Проверка производительности на мобильном уровне нагрузки (ограничение DPR, лимиты частиц).

## Этап F2 — Звук и полировка (P2)
1. Синтезированные SFX с троттлингом, простая музыка-пульс.
2. Hit-stop, слоу-мо, анимации UI.

## Этап G — Тестирование (P0 на каждом шаге)
1. `tsc` без ошибок.
2. Headless-бот в Node: прогон всех уровней, проверка завершаемости, времени, нагрузки (кол-во сущностей), отсутствия исключений.
3. Стресс-тест производительности (сотни зомби).
4. Ручная проверка в браузере: переходы экранов, управление, визуал.
